# TUSI 발사–유도 회수 통합 시나리오

이 문서는 제공된 ORK·ENG와 현재 파라포일 제어 모델로 실행할 수 있는 **전체 미션 시험 시나리오**다. 실제 발사 운용 승인서나 실물 펌웨어의 완성된 상태머신은 아니다. 화면에서 준비·점화·전개를 표시해도 하드웨어 명령은 전송하지 않는다.

## 1. 미션 시작 전에 결정하는 값

- 목표는 발사점을 원점으로 한 동·북 좌표와 허용 반경으로 지정한다. 기본 예시는 동쪽 250 m, 북쪽 350 m, 반경 25 m다.
- 상승 데이터는 ORK 저장 궤적 또는 실측/이론 ENG 기반 수직 상승 모델에서 선택한다. ORK 모드는 OpenRocket을 새로 실행하지 않는다.
- 서보/기구 설정, PD 이득, 실제 모델과 제어기의 선회 이득, 바람·센서 오차·지연을 지정한다.
- 준비 상태와 동체 ARM 버튼 확인은 실제 운용에서 탑재 소프트웨어가 담당한다. 현재 시뮬레이션은 준비가 완료됐다고 가정하며, 원격 ARM 버튼을 만들지 않는다.
- 실제 시스템에서는 GPS 위치, 추정 방위, 고도, 서보 상태의 유효성 확인이 필요하다. 현 시뮬레이터는 회수 시작 이후의 가상 센서만 계산한다. 발사 전 센서 준비를 자동 검증했다고 해석하지 않는다.

## 2. 처음부터 끝까지의 기본 흐름

| 단계 | 기본 시각 | 화면과 계산 동작 | 전환 근거 |
| --- | ---: | --- | --- |
| 발사대 대기 | T − 3~0 s | 로켓은 발사대, 낙하산은 접힌 상태, 조향 꺼짐 | 설정한 대기 시간 |
| 점화·동력 상승 | T + 0~1.635 s | ORK 로켓이 상승, 저장된 추력에 따라 불꽃 표시 | ORK 상승 샘플과 추력 종료 이벤트 |
| 관성 상승 | T + 1.635~9.506 s | 불꽃이 사라지고 최고점까지 상승, 낙하산 접힘 | ORK의 최대 고도 샘플 |
| 낙하산 전개 | T + 9.506~11.306 s | 캐노피가 펴지는 모습을 표시, 조향 꺼짐 | 전개·안정화 총 3초 중 앞 60%라는 시나리오 가정 |
| 자세 안정화 | T + 11.306~12.506 s | 캐노피 전개 상태에서 회수 모델 초기조건으로 연결 | 나머지 40%의 가정한 전환 |
| 회수 비행 | T + 12.506 s부터 | 가상 GPS·방위·선회율로 목표 PD를 계속 갱신 | 회수 물리 모델 + 센서 유효성 |
| 지면 도달 | 기본 예시 T + 약 163.708 s | 착지 좌표, 목표 오차, 최대 당김·선회율, 제어 로그 확인 | 회수 모델의 고도 0 교차 보간 |
| 결과 유지 | 착지 후 2 s | 마지막 자세를 유지하고 결과를 보여줌 | 표시용 유지 시간, 충격·정지 동역학 해석 아님 |

ORK의 최고점 **이벤트**는 9.556 s이고 최대 고도 **샘플**은 9.506 s다. 현재 연결은 기존 회수 모델과 동일하게 샘플을 사용한다. 실제 최고점 검출기를 검증한 결과가 아니다. 실측 ENG를 선택하면 추력 종료와 최고점 시각도 해당 상승 계산으로 바뀐다.

전개 구간은 최고고도 390.242 m에서 기본 고도 손실 20 m를 적용한 370.242 m까지 내려가는 단조 보간이다. 전개 시간과 고도 손실은 독립적인 가정이다. 사출·노즈 분리·드로그·캐노피 팽창력·진자 자세를 연속 물리로 계산하지 않는다. 두 기존 모델을 갑자기 화면 이동시키지 않고 연결하는 시각적 전환이다.

## 3. 회수 단계에서 계속 반복되는 제어

1. 센서 패킷을 개별 주기와 지연에 따라 받는다. 참 위치를 제어기에 직접 주지 않는다.
2. GPS 위치를 샘플 나이와 지상 속도로 보정하고 목표까지의 거리·방위를 계산한다.
3. GPS 속도와 추정 방위, 가정 수평 대기속도로 추정한 바람을 이용해 지령 방위를 보정한다.
4. `Kp × 방위 오차 − Kd × 측정 선회율`로 선회율 지령을 만든다.
5. 제어기의 선회 보정 이득으로 차등 줄 당김을 구하고, 최대 당김과 변화율을 제한한다.
6. 유격·정적 하중·줄 탄성을 고려해 좌우 모터 각도 명령으로 바꾼다.
7. 물리 모델은 모터 응답·줄 장력·실제 당김·선회를 계산한다. 새 위치를 다시 센서로 관측한다.

낙하산 전개 애니메이션 동안 PD가 작동하는 것처럼 표시하지 않는다. 회수 시작 직후에도 필요한 센서 패킷이 아직 도착하지 않았다면 중립을 유지한다. GPS 등이 시간초과하면 시험용 중립 정책으로 전환하고 센서 복구 후 재개한다.

현재는 목표를 계속 향하는 PD이며, 목표를 지나친 뒤 다시 돌아올 수 있다. 별도 FINAL_DESCENT 유도, 고도별 최종 접근, 플레어와 착륙다리는 구현하지 않았다. 최근접 거리와 착지 오차를 구분하며 미착지를 성공으로 판정하지 않는다.

## 4. 두 시간 기준

- **T=0**: 점화 기준 전체 미션 시각. 전체 화면, 단계 버튼, `mission.csv`에 사용한다.
- **R=0**: 회수 모델 시작. 기존 수동 당김 시간, GPS 끊김 시간, `trajectory.csv`와 `control_log.csv`에 사용한다.
- 기본 관계는 `T = R + 12.506 s`다. 전개 시간이나 상승 모델이 달라지면 이 오프셋도 변한다.
- 예를 들어 GPS 끊김 설정 R=20~26 s는 기본 전체 미션에서 T=32.506~38.506 s다. 센서 시간초과는 마지막 측정의 나이에 따라 별도로 판정한다.

## 5. 화면에서 실행하는 순서

1. `python3 -m simulation.server`를 실행하고 `http://127.0.0.1:8765/`를 연다.
2. **기본 미션**을 누르거나 목표·바람·PD 값을 설정한 뒤 **전체 미션 계산·재생**을 누른다.
3. **처음부터 재생**은 계산된 결과를 발사대부터 다시 보여준다. 설정을 바꾼 후에는 먼저 재계산한다.
4. 단계 버튼으로 점화·전개·회수·착지 시점에 바로 이동한다. **발사·전개·착지는 1×로 보기**를 켜면 짧은 구간을 확인하기 쉽다.
5. **기체 따라가기**, **로켓 확대**, **전체 경로**로 전환한다. **회수 구간만**을 선택하면 기존 조향 시험 화면처럼 R=0부터 본다.
6. **전체 미션 CSV**, **회수 궤적 CSV**, **제어 주기 로그 CSV**를 저장한다. 전체 미션 CSV에는 `phase`, `data_source`, `flight_model_valid`, `recovery_t_s`가 있어 데이터 근거와 시간 기준을 구분할 수 있다.

## 6. 비교할 시험과 판정

| 시험 | 바꾸는 조건 | 확인할 결과 |
| --- | --- | --- |
| 기본 미션 | 기본 목표와 동일 난수 시드 | 상승/전개 중 조향 비활성, 회수 시작 후 반복 제어, 지면 도달 |
| 돌풍 | 돌풍 표준편차 증가 | 줄 지령 변화, 실제 당김, 포화 비율, 착지 오차 |
| GPS 끊김 | R=20~26 s | 오래된 측정값의 나이, 시간초과 중립, 복구 후 재개 |
| 줄 단계 시험 | 좌/우 각도와 당김 시간 | 당김 mm, 선회율, 같은 시각의 이동 차이 |
| 짧은 계산 시간 | 회수 계산 시간 감소 | 공중에서 종료되고 미착지로 표시되는지 |
| 보정 불일치 | 물리/제어기 선회 이득을 따로 변경 | 모델 오차가 추종에 미치는 영향 |

착지 오차는 현재 모델·입력·난수 시드로 다시 계산해 화면에서 확인한다. 가정 민감도 비교로 선회 효과가 없거나 반대인 경우까지 확인할 수 있다. 이 값은 실제 성공률이나 착륙 정확도를 뜻하지 않는다. 6.5 V의 실제 서보 성능, 드럼 치수, 조향줄 하중과 파라포일 공력·선회 계수는 여전히 보정이 필요하다.

상승 자세는 ORK 저장 기체 축 방향을 사용한다. 최고점 횡이동 약 21.53 m, 수직 대비 약 22.28° 기울어짐을 발사대 고정 카메라에서 확인할 수 있다. 롤 축 회전은 미복원이며 전개 중 자세는 시각적 보간이다. ENG 선택은 계속 1D 수직 상승 근사다.
