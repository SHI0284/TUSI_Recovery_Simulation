# TUSI 낙하산 조향 물리 시뮬레이터

모터 회전각 → 드럼 권취 → 줄 유격·탄성·장력 → 좌우 유효 당김 차이 → 선회 → 비행 경로를 계산한다. 실제 파일에서 가져온 로켓 데이터와 **아직 측정하지 않은 기구·공력 파라미터**를 구분하는 축약 모델이다. 실물 성능이 검증된 디지털 트윈이나 CFD/유연체 해석은 아니다.

발사부터 착지까지의 단계·전환 근거·시간 기준과 시험 방법은 [전체 미션 시나리오](../simulation/mission_scenario.md)에 정리했다.

## 실행

Python 3.10 이상, 표준 라이브러리만 필요하다. 저장소 최상위에서:

```bash
python3 -m simulation.server
```

브라우저에서 <http://127.0.0.1:8765>를 연다. 기본은 발사대 대기부터 GPS 목표 지점 추종과 착지까지의 전체 미션이다. 전체 비행의 폐루프 계산을 먼저 수행하고, **센서·제어 로그와 함께 3D로 반복 재생**한다. 외부 GPS 스트림과 연결된 실시간 하드웨어 제어는 아니다. 목표 위치·PD 이득·바람 등을 바꾸면 `계산하고 재생`으로 다시 계산한다. 같은 조건의 무조향 경로와 자동 비교한다. 토크 부족과 잘못된 입력을 표시한다. 궤적 CSV, 결과 JSON, 설정 JSON을 저장하거나 설정을 다시 불러올 수 있다. 연결은 로컬 PC에만 열며 실제 비행 하드웨어와 통신하지 않는다.

```bash
# 기본: ORK 최고점 이후, 가상 GPS/추정 방위로 목표 추종
python3 -m simulation.run
# 오른쪽 모터 각도별 수동 입력 비교
python3 -m simulation.run --mode manual --sweep
# 제공된 실측 / 이론 추진 모터로 근사 상승부터 계산
python3 -m simulation.run --initialization measured --output simulation/results/measured
python3 -m simulation.run --initialization theoretical --output simulation/results/theoretical
# 저장한 설정 사용
python3 -m simulation.run --config simulation/config.json
# 물리·입력 검증
python3 -m unittest discover -s simulation/tests -v
```

결과는 `simulation/results/`에 저장한다. `mission.csv`는 점화 기준 T 시각의 전체 단계/근거/전개 표시를 포함하고, `control_log.csv`는 매 제어 주기의 센서값·유효 상태·PD 항·요청 당김·각도 지령, `trajectory.csv`는 안정 비행 시작을 0초로 한 물리/센서/제어 시계열, `result.json`은 적용 설정·가정·상승 경로·회수 궤적·요약, `sources.json`은 입력 파일 요약, `angle_sweep.csv`는 오른쪽 회전각 0~270°의 비교다. 실제 착지 전 최대 시간이 끝나면 `landed=false`이며 UI도 착지점 대신 종료점으로 표시한다. 조건별 종료 시각이 다를 수 있으므로 CSV의 시간을 함께 확인한다.

ORK의 주 낙하산은 **원형 지름 1.3 m, 0.454 kg, 줄 6개, 길이 1.1 m**다. 드로그는 지름 0.6 m다. 두 장치 모두 `deployevent=apogee`이며, 저장된 `deployaltitude=100/200`은 선택된 전개 이벤트가 아니다. 따라서 고도 100 m에서 주 낙하산이 펴지는 것으로 잘못 해석하지 않는다.

ORK의 실제 최고점 이벤트는 9.556 s, 저장된 최대고도 데이터 샘플은 9.506 s다. 시뮬레이터는 최대고도 **샘플**을 사용한다. 기존 비행의 바람·모터 설정은 그대로이며 UI의 바람은 이후 파라포일 구간에만 적용된다.

사용자 제공 [Amazon 제품 링크](https://www.amazon.com/dp/B00VW7MYV8)는 직접 조회 시 503 응답이었다. 같은 ASIN의 검색 결과에서 HENGDA KITE 2.5 m, 2줄 파라포일 연으로 식별했지만, 제조사 면적·공력·브라이들 자료는 확보하지 못했다. **2.5 m를 2.5 m²로 사용하지 않으며**, ORK 원형 낙하산의 직경도 파라포일 면적으로 치환하지 않는다. `canopy_area_m2=1.8`은 측정이 필요한 예시값이다. 질량은 ORK의 454 g을 유지한다.

## 모델과 가정

좌표는 East/North/Up, 고도는 발사 지면 기준, 방위 0°는 북쪽이며 시계 방향이 양수다. 바람은 공기가 **이동하는 방향**의 성분이다. `wind_east_mps=+3`은 동쪽으로 3 m/s 움직이는 공기다. 기상 풍향의 '불어오는 방향'과 구분한다.

### 조향 모터와 줄

좌우 독립 위치 서보 2개, 일정 드럼 반지름, 이상적인 위치 유지 브레이크를 가정한다. 회전각은 중립에서 감아들이는 양수 각도다. 연속 회전 서보의 PWM–속도 제어나 하나의 축으로 양쪽 줄을 반대로 감는 장치는 별도 구현이 필요하다.

```text
드럼 권취량 = r θ
줄 기하학적 이동량 s = r θ / p                   (p: 도르래 비율)
줄 유효 당김 δ = max(0, (s - 유격 - F0/k줄) / (1 + k당김/k줄))
줄 장력 F = F0 + k당김 δ
모터 요구 토크 = F r / (효율 × p)
감기 속도 한계 = 무부하 각속도 × max(0, 1 - 요구 토크/정지 토크)
```

`F0 = 전체 공기력 크기 × 조향줄 하중 비율 / 2`를 각 줄에 적용한다. 주 하중을 받는 2줄인지, 별도 브레이크 줄인지에 따라 하중 비율이 크게 달라진다. 기본 0.15는 측정값이 아니다.

사용자가 지정한 **Waveshare ST3235**의 [제조사 제품 사양](https://www.waveshare.com/product/accessories/st3235-servo.htm)과 [공식 위키](https://www.waveshare.com/wiki/ST3235_Servo)를 반영했다. 12 V 기준 정지 토크 `30 kgf·cm × 0.0980665 = 2.941995 N·m`, 무부하 속도 `45 rpm × 6 = 270°/s`를 참조값으로 사용한다. 표기의 0.222 s/60°는 반올림된 값이다. 제품 표와 위키의 공급 전압 상한은 12/12.6 V로 다르다.

**회로도를 추가 확인한 결과, 서보 설계 전압은 6.5 V다.** `servo_supply_voltage_v=6.5`로 기록했고, 확보한 성능 자료의 전압은 `motor_performance_voltage_v=12`로 분리했다. 두 전압이 다르면 화면과 JSON에 전압 불일치를 명시한다. 다른 전압의 토크·속도를 임의 비례 환산하지 않으므로 현재 계산은 **12 V 성능 참조 시나리오**이며 회로도대로 6.5 V를 공급했을 때의 실물 예측이 아니다. 6.5 V 토크·속도 자료 확보 후 두 성능값과 성능 자료 전압을 함께 갱신해야 한다. 전압 숫자만 바꿔도 토크·속도가 자동 변하지 않는다.

ST3235의 위치 명령은 0~4095, 분해능은 360°/4096이다. 현재 270° 설정은 **줄 권취 기구의 임시 제한**이며 모터 자체의 최대각이 아니다. 절대각 원점·감기는 방향·동작 모드는 아직 미확인이다. 위치 명령을 360°/4096 단위로 양자화하고 명령 큐 지연·가속 및 감속 프로파일을 적용한다. 기본 명령 지연 0.04 s, 가감속 900°/s²는 실측값이 아닌 시험 가정이다. 제조사 내부 제어기·통신 재시도·다회전 모드를 재현하지 않으며, 목표 위치와 기구 끝에서는 속도를 0으로 제한하는 근사다. 가감속을 0으로 두면 이전의 속도 제한 모델이 된다. 모델의 선형 토크–속도 관계도 실측 곡선이 아니다. 정지 토크를 연속 운전 토크로 해석하면 안 된다.

제조사 참조 사양은 `result.json`의 `servo_reference`에 남고, 토크·속도를 수정하면 `uses_reference_torque_speed=false`로 기록한다. 모터 질량은 기존 ORK의 제어장치 질량에 포함됐을 가능성이 있어 추가하지 않았다. 실제 중복·누락 여부는 질량 명세로 확인해야 한다.

토크가 부족하면 감기가 멈춘다. 풀기는 속도 제한을 적용하고 위치 유지는 이상적인 브레이크로 처리한다. 역구동·발열·전류·전원 강하·기어 탄성·다층 감김은 계산하지 않는다. 이런 한계 때문에 과부하 결과는 실제 모터 거동의 완전한 예측이 아니다.

### 파라포일 비행

회전율은 줄 당김 차이에 비례하는 목표값을 1차 지연으로 추종한다. 이 응답 형태는 [Ward & Costello의 연구](https://guidedparafoils.org/wp-content/uploads/2019/06/Adaptive_Glide_Slope.pdf)를 참고했으며, 계수는 해당 논문에서 이 제품용으로 가져온 값이 아니다. 실제 캐노피 기울기와 줄 변형이 제어 응답에 중요하다는 점은 [Slegers & Costello의 실험·모델 비교](https://digitalcommons.georgefox.edu/mece_fac/49/)에서도 다룬다. 이 모델은 해당 연구의 9자유도 모델을 재현한 것이 아니다.

```text
평균 당김 = (δ좌 + δ우)/2
CL = CL0 + CL당김 × 평균 당김
CD = CD0 + CD당김 × 평균 당김
선회율 목표 = K선회 × (δ우 - δ좌), 한계 적용
선회율 변화 = (선회율 목표 - 선회율)/시정수
동압 q = ρ V²/2; L = q S CL; D = q S CD
a바람 = ∂W/∂t + hdot ∂W/∂h
a평행 = a동 sin(ψ) + a북 cos(ψ)
a직각 = a동 cos(ψ) - a북 sin(ψ)
Vdot = -D/m - g sin(γ) - cos(γ) a평행
γdot = (L cos(φ)/m - g cos(γ) + sin(γ) a평행)/V
ψdot = 선회율 - a직각/(V cos(γ))
φ = atan(V cos(γ) × 선회율 / g)
Edot = V cos(γ) sin(ψ) + 바람동
Ndot = V cos(γ) cos(ψ) + 바람북
hdot = V sin(γ)
```

ψ는 대기 상대 속도 벡터의 수평 방향, γ는 비행 경로각, φ는 선회에 대응하는 근사 뱅크각이다. 가상 기체 방위는 ψ를 기본 0.25 s 시정수로 따라가는 별도 경험적 상태다. 돌풍으로 속도 벡터 방향이 급변하는 것을 그대로 자이로 회전으로 취급하지 않는다. 이 방위 지연은 실측 관성모멘트·공력 모멘트에서 계산된 값이 아니다. 비행 운동은 RK4로 적분하고 모터·선회 응답은 단계마다 갱신한다. 선회율과 뱅크각 제한을 적용한다. 질점 운동에 경험적 선회 응답을 결합했으며, 관성모멘트 기반 강체 6자유도 해석이 아니다. 밀도는 설정된 상수다. 바람은 평균 성분 + 고도에 비례하는 전단 + 시간 상관이 있는 확률 돌풍(OU 과정)을 포함한다. 0.1초 고정 격자로 생성하고 시간 보간하며, 난수 시드가 같으면 제어 모드·적분 간격과 무관하게 동일한 돌풍 시계열을 사용한다. 전단 때문에 고도가 다른 비행에는 같은 시각에도 서로 다른 바람이 작용한다. 바람은 지상 속도에 더하며, 기본적으로 물질미분 관성항을 대기 상대 속도·경로각·방향에 반영한다. 따라서 바람이 바뀌었다고 질량의 지상 속도가 그대로 즉시 변하지 않는다. `wind_inertia_enabled=0`은 비교용 이류 전용 모델이다. 수직 바람, 수평 공간 난류, 캐노피 국소 비정상 공력·천의 변형·기체 진자 운동은 포함하지 않는다. 실제 지역의 날씨 자료가 아니다.

기본값은 오른쪽을 당기면 우회전한다. 실제 장착 방향·브라이들 특성에 따라 반전될 수 있으므로 `turn_gain_rad_s_m`은 음수도 허용한다. `max_valid_brake_m` 밖에서는 경고하며 실제 실속을 계산하지는 않는다.

### 상승과 전개

- `ork`: 저장된 상승 위치·고도와 기체 축 방향, 피치/요/롤 각속도를 가져온다. 최고점 횡이동은 약 21.53 m, 기울기는 수직 대비 약 22.28°다. 자세를 화면에 연결하고 발사대 고정 카메라에서 기준 수직선과 실제 상승 궤적을 비교한다. 축 주위 롤 각도는 복원하지 않는다. [OpenRocket 24.12 `SimulationStatus.storeData`](https://github.com/openrocket/openrocket/blob/release-24.12/core/src/main/java/info/openrocket/core/simulation/SimulationStatus.java)의 정의에 맞춰 `zenith` 라벨 값은 실제로 고도각 atan2(z, 수평), 방위는 atan2(동, 북)로 해석한다. 현재 OpenRocket을 다시 실행하는 것이 아니므로 UI 바람을 바꿔도 상승 궤적은 바뀌지 않는다.
- `measured` / `theoretical`: 해당 ENG 추력으로 수직 질점 상승을 다시 계산한다. 항력은 일정 Cd, 연료 감소는 누적 충격량 비례, 횡방향 운동·발사대 각도는 생략한다. OpenRocket의 Barrowman 6자유도 결과와 일치하는 모델이 아니다. 기본 예시에서 최고고도는 약 283.5 / 371.8 m이며, 실측 곡선 사용 결과도 실제 고도 측정값은 아니다.
- 회수 비행은 최고점에서 설정 고도 손실(기본 20 m)을 뺀 위치에서 **이미 팽창·안정화된 정상 활공 속도**로 초기화한다. 그 사이의 시간·변위·전개력은 해석하지 않는다. 전체 미션 화면에서는 설정한 전개 시간(기본 3초)에 걸쳐 두 궤적을 시각적으로 연결한다. 이 보간과 캐노피 팽창 표시는 개방 충격·분리·전개 비행을 연속 물리로 해석한 것이 아니다.
- 전체 로켓·연소 후 모터가 연결된 질량을 사용한다. 분리된 노즈 등 별도 물체를 해석하지 않는다. 드로그는 주 낙하산 비행 중 항력을 만들지 않는다고 가정한다. 실제로 계속 전개돼 있다면 드로그 항력·연결 구조부터 보완해야 한다.

### 제어 입력

- `target` (기본): 센서 기반 목표 지점 추종. `guidance.py`의 `TargetPD`는 가상 센서 관측만 받으며 물리 모델의 참 위치·참 방위·참 바람에 접근하지 않는다.
- `neutral`: 양쪽 중립. 같은 바람 시드의 기준 비행이다.
- `manual`: 시작~종료 시간에 지정 각도 입력. 줄 당김과 반응을 식별하기 위한 단계 입력이다.
- `heading`: 고정 목표 방위를 유지하는 기존 이상적 센서 비교용 PD. 참 방위와 참 선회율을 직접 사용하며 목표 지점 추종 모드와 구분한다. 이 모드에는 줄 유격 보상이 없어 기본 기구에서 약 3.6° 잔류 오차가 생긴다.

`controller_period_s`는 적분 시간 격자로 양자화된다. 기본 제어 주기 0.05 s와 적분 0.02 s 조합은 실제 갱신 간격이 0.04/0.06 s로 번갈아 나타난다. 로그에는 실제 갱신 시각을 기록하며, 당김 변화 제한에도 실제 경과 시간을 사용한다. 센서 주기 역시 적분 시간 이상이어야 한다.

### 가상 센서와 목표 PD

`environment.py`의 센서 모듈은 개별 갱신 주기·전송 지연·측정 오차를 갖는 GPS, 방위/자이로, 기압 고도 패킷을 만든다. 샘플 시각과 현재 시각의 차이로 유효성을 판단한다. 0 좌표는 정상 위치다. GPS 위치는 발사점 기준 동·북 m이며 실제 펌웨어에서는 WGS84 위경도에서 지역 좌표로 변환해야 한다. GPS 지상 이동 방향과 기체 방위는 서로 다른 값이다.

기본값은 GPS 5 Hz/지연 0.2 s/위치 오차 σ=1.5 m, 추정 방위·자이로 50 Hz/지연 0.02 s, 기압 고도 10 Hz/지연 0.05 s이다. GPS에는 백색 잡음 외에 σ=0.8 m·상관 시간 30 s의 느린 OU 편향, 자이로에는 0.1°/s 고정 편향을 추가한다. **설치 센서의 확인된 사양이 아니라 설정 가능한 시험 가정값이다.** 방위는 이미 자세 추정기가 제공한다고 가정한다. 원시 가속도·자력계·자이로 융합을 구현한 것은 아니다. 기압 고도는 신선도 검사에 사용하고 최종 접근 유도에는 아직 사용하지 않는다.

```text
현재 위치 추정 = 마지막 GPS 위치 + GPS 지상 속도 × 샘플 나이
목표 방위 = atan2(목표 동 - 현재 동, 목표 북 - 현재 북)
바람 추정 = 저역통과(GPS 지상 속도 - 가정 수평 대기속도 × 방위 단위벡터)
지령 방위 = 목표 방위 + 추정 횡풍을 상쇄하는 제한된 기수 보정각
방위 오차 e = wrap(지령 방위 - 측정 방위), [-π, π)
선회율 지령 = Kp × e - Kd × 측정 선회율
차등 당김 지령 = 선회율 지령 / 제어기에 설정한 선회 보정 이득
→ 최대 당김 제한 → 변화율 제한 → 좌우 줄 배분
→ 정적 줄 하중/유격/탄성을 고려한 역변환 → 모터 각도 지령
```

D항은 목표값 변화에 따른 순간적인 지령 도약을 피하기 위해 측정 선회율에 적용한다. 이 값은 변화하는 목표 방위의 오차를 단순 차분한 D항과 다르다. 제어기 보정 이득 `controller_turn_gain_rad_s_m`과 실제 모델 이득 `turn_gain_rad_s_m`을 분리해 보정 오차를 시험할 수 있다. 양쪽 부호가 실제 줄 연결 방향과 일치해야 한다. 물리 모델은 동적 장력을, 제어기는 명목 정적 장력을 쓰므로 요청 당김과 실제 당김은 약간 다를 수 있다.

GPS/방위/기압 고도 중 하나가 `sensor_timeout_s`를 넘으면 이 시험의 정책은 양쪽 중립이다. 새 센서 값이 오면 추종을 재개한다. **실제 비행용 센서 상실 대응 정책으로 검증된 것은 아니다.** 센서 패킷 지연 동안에는 마지막 측정값을 유지한다. 추정 풍속이 비행 능력을 넘는 경우 UI에 도달 불가 추정을 표시한다. 바람 추정은 가정 대기속도와 비동기 센서 오차에 영향을 받으며 실제 풍속계 값을 대신한다고 보장하지 않는다.

목표 추종을 계속 수행하므로 목표 근처에서 선회하거나 통과한 뒤 재접근한다. 현재 모델에는 고도 기반 접근 경로 계획·대기 선회 전략·플레어가 없다. `closest_target_distance_m`(중간 최근접 거리)와 `target_error_m`(착지 또는 종료 오차)을 구분한다. `landed_in_target`은 **실제로 지면에 도달하고 설정 목표 반경 안에 있을 때만** 참이다.

### 3D 화면과 비교 실험

- **낙하산 따라가기**: 마우스 드래그로 주변을 돌려 보고 휠로 확대한다. 실제 계산된 방위·뱅크각·드럼 각도를 사용한다. 로켓은 ORK의 타원형 노즈·몸통·사다리꼴 핀 4개·보트테일·런치 러그를 실제 치수/축방향 배치로 재구성한다. 총길이 1.604375 m, 몸통 지름 0.104 m, 노즈 0.28 m, 몸통 1.3 m, 보트테일 0.024375 m다. 핀의 루트/팁/후퇴/높이/두께를 보존하며 에어포일 단면은 평판으로 근사한다. 색상·서보 장착·줄 연결은 개념 표현이고 전개 후 노즈 분리는 아직 해석하지 않는다. 내부 질량 자리표시자를 실제 착륙다리 형상으로 만들어내지 않는다.
- **전체 경로**: 목표 원, 조향/무조향 궤적, 현재 위치, 지상 투영을 표시한다. 기체는 보기 위해 8배 확대한다. 궤적은 실제 m 좌표다.
- **캐노피 변형**: 유효 줄 당김에 연결된 6배 시각 강조다. 천의 탄성·실제 형상 변화를 해석한 결과가 아니다. 외형은 HENGDA KITE 2.5m 빨간색 모델의 동일 제품명 판매 페이지가 제공하는 Amazon 호스팅 사진을 참고한다. 빨간 앞부분과 개방 셀, 검정 띠·밝은 뒤 패널, 두 줄로 모이는 브라이들을 표현했다. 표시 폭 2.5 m는 제품명, 시위 0.85 m는 동일 UPC 판매자 표기를 사용한 시각화값이며 실측/제조사 도면 치수는 아니다. 물리 모델의 유효 면적 1.8 m²를 제품 면적으로 확정한 것이 아니다. 부풀음, 셀 수, 브라이들 길이와 로켓 연결 위치는 근사다. `data/parafoil_visual_reference.json`에 직접 Amazon 페이지 조회 실패·사진 대체 출처·식별 근거·미확인 항목과 사진 해시를 보존한다. 화면의 원본/치수 상세에서 참고 사진을 볼 수 있다.
- **반복 재생 / 시간 슬라이더**: 한 번의 펄스 애니메이션이 아니라 전체 비행의 수천 회 제어 계산 결과를 재생한다. 반복 체크를 끄면 종료 시점에서 멈춘다. 마우스로 카메라를 돌리는 동안에도 센서·제어 값이 갱신된다.
- **4개 프리셋**: 목표 추종, 강한 돌풍, 20~26초 GPS 끊김, 무풍 수동 줄 단계 시험. 프리셋은 모든 설정을 해당 기본 시나리오로 초기화한다.
- **모터 지령·응답 그래프**: 시간 범위를 현재 주변 2초로 줄이면 지령·수신 목표·실제 회전각의 지연과 가감속을 확인할 수 있다. 재생 슬라이더로 관측 구간을 이동한다.
- **회전각별 비교**: 현재 입력을 사용해 좌측 중립/우측 0~270°를 30초씩 계산한다. 수동 당김 시간 설정을 사용한다. 최대 유효 당김과 선회율, 무조향 대비 동·북 변위와 위치 차이를 표로 표시한다. 일찍 착지한 행은 종료 시각이 다르므로 같은 시각의 응답으로 비교하면 안 된다. 이는 줄 1 mm당 이동 거리가 일정하다는 모델이 아니다.

3D 렌더러는 Three.js r180을 `web/vendor/`에 고정해 저장했으며 외부 CDN에 연결하지 않는다. 라이선스는 `THREE-LICENSE.txt`다. WebGL을 사용할 수 없으면 2D 경로와 제어 로그를 계속 사용할 수 있다.

## 실제 장치로 보정할 항목

1. 모터 모델은 **ST3235**, 회로도상 서보 공급은 **6.5 V**로 확인됐다. 부하 중 전압·속도·토크, 설정된 동작 모드, 원점과 권취 범위는 실물에서 보정한다.
2. **드럼 유효 지름, 좌우 줄 연결 방식, 도르래 비율**. 모터 각도별 실제 줄 이동량을 측정한다. 기본 반지름 10 mm에서 180°의 이상 권취량은 31.416 mm다.
3. **줄 유격·강성·하중**. 줄 장력과 실제 캐노피 조작부 이동량을 함께 측정한다. 초기 길이 1.1 m만으로 줄의 탄성 강성을 확정할 수 없다.
4. **파라포일 면적·브라이들·트림과 활공 성능**. 안정 비행의 대기속도와 하강률로 CL/CD를 식별한다. 지상 GPS 속도에서 바람을 빼야 한다.
5. **차등 당김에 따른 선회율·지연·방향**. 시간, 좌우 실제 당김량, 방위, 선회율을 기록해 `K선회`와 시정수를 식별한다. 연의 전체 제어줄을 당기는 경우 후연 브레이크만 당기는 모델과 다를 수 있다.
6. 드로그 잔류 여부, 안정화 고도 손실, 실제 회수 시 매달리는 질량을 확인한다.

모터 각도에 따른 당김과 이동량은 **회전각별 비교**에서 현재 설정으로 계산한다. 바람·하중·입력 지속 시간·선회 계수에 따라 결과가 달라진다. 계산된 mm당 이동량이나 PD 이득을 실측 보정 없이 실물 성능으로 해석하지 않는다.

## 검증 범위

50개 자동 검사는 원본 해시, 전압 불일치 표시·임의 환산 방지, ST3235 단위 환산·사용자 덮어쓰기 표시, 추력 적분·보간, ORK 질량, 드럼 기하, 줄 탄성 평형·도르래 비율, 유격, 토크 부족, 속도·각도 한계, 활공 평형, 좌우 대칭, 동시 당김, 바람 이류, 지면 도달 보간, 시간 간격 수렴, PD의 유격 오차, 추진 곡선 변경, 입력 오류·시간 종료를 확인한다. 무풍·이상 액추에이터의 0.02→0.01 s 회귀 비교에서 30초 위치 차이 0.5 m 미만·방위 차이 0.15° 미만을 요구한다.

미션 검사에서는 단계 순서·단조 시간축·전개 위치 연결·상승 중 조향 비활성·회수 해 보존·시간 제한 미착지·실측 ENG 시각·시나리오 설정 범위를 확인한다. ORK 외형 파서는 총길이·노즈 형상·부품 연결·핀 치수와 몸통 후단 배치를 검증한다. 추가로 센서 지연·샘플 유지·끊김·복구, 0 좌표 유효성, PD 부호·각도 래핑·미분 감쇠·변화율 제한, 실제 물리 변수와 제어기 보정의 분리, 강풍 도달 불가 추정, 동일 시드 재현성, 기본 목표 추종의 무조향 대비 오차 감소, 미착지 성공 판정 방지를 확인한다. 실제 Chromium에서 3D 렌더링, 네 가지 프리셋, GPS 끊김 상태, 모바일 가로 넘침, CSV 다운로드를 점검했다.

추가 검사는 ORK 자세 좌표 변환, 명령 큐·분해능·초기 가속, 과부하 정지, 움직이는 질점에서 바람의 물질미분, 지상 속도의 관성 연속성, 재현 가능한 센서 편향, 대기 속도 방향과 기체 방위 분리, 조향 효과가 없는 경우를 확인한다.

이 검사는 수학·구현의 일관성을 검증한다. 실제 낙하산의 공력과 조향 성능 검증은 아직 수행하지 않았다.

## 이 캐노피가 실제로 조향 가능한가?

현재 답은 **미검증**이다. 링크의 HENGDA 두 줄 카이트는 별도 후연 브레이크가 달린 회수용 파라포일과 동일한 장치로 간주할 수 없다. 지상에서 두 줄로 유지되는 연의 안정성과, 4.276 kg 로켓을 매단 자유 비행의 안정성은 별도로 확인해야 한다. [Slegers & Costello](https://digitalcommons.georgefox.edu/mece_fac/3/)는 파라포일 형상·트림에 따른 롤/스키드 조향과 조향 효과가 사라지는 경우를 다룬다. 그 논문도 이 제품의 성능을 보증하지 않는다.

`rigging`은 원래 두 제어줄 / 별도 후연 브레이크줄 / 미확인의 기록이다. 선택만으로 공력 계수를 자동 변경하지 않는다. 기본 `control_load_fraction=0.15`는 조종부 일부 하중 가정이다. 실제 두 줄이 매달린 로켓의 전체 하중을 지지하면 이 가정이 맞지 않을 수 있다. 브라이들 각도·좌우 하중 비대칭은 현재 장력 모델에 없으므로 전체 하중 사례도 실측 장력을 대신하지 못한다.

화면의 **가정 민감도 비교**는 같은 난수 시드로 현재 가정, 선회 효과 절반/없음/반대, 모터 성능 절반, 명령 지연 최소 0.2 s, 조종줄 전체 하중, 센서 오차 증가의 8가지를 계산한다. 50%는 성능 저하 시험이며 12 V→6.5 V 환산이 아니다. 표는 가정의 영향이며 실제 성공률이나 검증된 오차 범위가 아니다. `model_assessment`에 미보정 상태와 줄 연결 기록을 저장한다.

실물 보정에 필요한 최소 기록은 시간, 실제 전압, 서보 지령·피드백 각도, 좌우 장력, 드럼 권취량, 캐노피 조작부 변위, GPS 위치/속도, 방위/각속도, 기압 고도다. 먼저 장치에서 각도→당김량·응답 지연·부하 속도를 식별하고, 별도로 안정 활공과 차등 당김의 선회 방향·이득·시정수를 확인해야 한다. 이 값들이 확보되기 전까지 화면의 캐노피 변형은 6배 강조된 설명용 표현이다.
